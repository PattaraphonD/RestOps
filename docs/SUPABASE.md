# ย้ายฐานข้อมูลไป Supabase (v2.0.0)

คู่มือนี้พาเจ้าของร้านเปิดใช้เซิร์ฟเวอร์ใหม่บน Supabase ทีละขั้น ใช้เวลาประมาณ 30–45 นาที
แอปหน้าตาและการใช้งานเหมือนเดิมทุกอย่าง เปลี่ยนแค่ "ที่อยู่เซิร์ฟเวอร์"

> **สิ่งที่ต้องมี:** คอมพิวเตอร์ที่มีโฟลเดอร์โปรเจกต์นี้และ Node.js (มีอยู่แล้ว) · อีเมลสำหรับสมัคร Supabase · ประมาณ 30 นาที
>
> **ความปลอดภัย:** รหัสผ่านฐานข้อมูลและรหัสผ่านเจ้าของร้านเก็บไว้เอง (เช่นในโปรแกรมจัดการรหัสผ่าน) อย่าส่งในแชตหรือใส่ไว้ในไฟล์ของโปรเจกต์

---

## ขั้นที่ 1 · สมัครและสร้างโปรเจกต์ (บนเว็บ)

1. ไปที่ **supabase.com** → **Start your project** → สมัครด้วยอีเมลหรือ GitHub
2. กด **New project**
   - **Name:** `restaurant-ops`
   - **Database Password:** กด **Generate a password** แล้ว **บันทึกเก็บไว้** (ต้องใช้ในขั้นที่ 3 และ 5)
   - **Region:** **Southeast Asia (Singapore)** — ใกล้ไทยที่สุด แอปจะเร็ว
   - **Plan:** ทดลองด้วย Free ได้ แต่ **ก่อนใช้งานจริงให้อัปเกรดเป็น Pro** (ประมาณ US$25/เดือน) เพราะ Free จะหยุดเมื่อไม่มีการใช้งาน 7 วัน และไม่มีสำรองข้อมูลรายวัน
3. รอโปรเจกต์สร้างเสร็จ (1–2 นาที) แล้วจด **Project ref** — ตัวอักษร 20 ตัวในที่อยู่หน้าเว็บ `supabase.com/dashboard/project/<project-ref>`

## ขั้นที่ 2 · เข้าสู่ระบบ Supabase จากคอมพิวเตอร์

เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วรันทีละบรรทัด:

```bash
npm install
```

(ติดตั้งเครื่องมือ Supabase เวอร์ชันที่ทดสอบแล้ว 3.1.0 ไว้ในโปรเจกต์ ไม่ต้องดาวน์โหลดเพิ่ม)

```bash
npx supabase login
```

เบราว์เซอร์จะเปิดขึ้นมาให้กดอนุญาต — กดยืนยันแล้วกลับมาที่ Terminal

## ขั้นที่ 3 · เชื่อมโปรเจกต์และสร้างตาราง

```bash
npx supabase link --project-ref <project-ref>
```

แล้วสร้างตาราง:

```bash
npx supabase db push --remote
```

ใส่รหัสผ่านฐานข้อมูล (จากขั้นที่ 1) เมื่อระบบถาม และตอบ `Y` ระบบจะสร้างตารางทั้งหมด (ล็อกไว้ให้เข้าถึงได้เฉพาะผ่านเซิร์ฟเวอร์ของแอปเท่านั้น)

## ขั้นที่ 4 · ติดตั้งเซิร์ฟเวอร์ของแอป

```bash
npx supabase functions deploy api --no-verify-jwt --use-api
```

ทดสอบ: เปิดเบราว์เซอร์ไปที่ `https://<project-ref>.supabase.co/functions/v1/api`
ต้องเห็นข้อความประมาณนี้: `{"ok":true,"data":{"service":"Restaurant Ops API","version":"2.0.0","database":"supabase"}}`

## ขั้นที่ 5 · สร้างบัญชีเจ้าของร้าน

1. ในหน้าโปรเจกต์ Supabase กดปุ่ม **Connect** (ด้านบน) → แท็บ **Connection String** → เลือก **Session pooler** → คัดลอก **URI**
2. แทน `[YOUR-PASSWORD]` ใน URI ด้วยรหัสผ่านฐานข้อมูลจากขั้นที่ 1
3. รัน:

```bash
node tools/supabase_setup.mjs
```

วาง URI เมื่อระบบถาม ระบบจะแสดง **ชื่อผู้ใช้ `owner` และรหัสผ่านชั่วคราว** — จดไว้
(URI ไม่ถูกบันทึกลงเครื่อง)

## ขั้นที่ 6 · ทดลองใช้ก่อนเปลี่ยนทั้งร้าน

1. เปิดแอป → หน้าเข้าสู่ระบบ → **การเชื่อมต่อเซิร์ฟเวอร์** → วาง `https://<project-ref>.supabase.co/functions/v1/api`
2. เข้าสู่ระบบด้วย `owner` และรหัสผ่านชั่วคราว → **เปลี่ยนรหัสผ่าน** ที่ เพิ่มเติม → บัญชีของฉัน
3. ลองเพิ่มซัพพลายเออร์ 1 ราย → ปิดแอปแล้วเปิดใหม่ → ต้องยังอยู่
4. ใน Supabase เปิด **Table Editor** → ตาราง `Suppliers` → ต้องเห็นรายการที่เพิ่ม

## ขั้นที่ 7 · เปลี่ยนทั้งร้านมาใช้ Supabase

บอกผู้ช่วย (Claude) ว่า "ทดสอบผ่านแล้ว" พร้อม **ที่อยู่เซิร์ฟเวอร์** (ไม่ต้องส่งรหัสผ่านใดๆ) ผู้ช่วยจะ:
- ใส่ที่อยู่ใหม่ใน `app/config.js` แล้ว commit
- จากนั้นคุณ deploy แอปขึ้น Vercel ตามปกติ — พนักงานทุกคนจะใช้เซิร์ฟเวอร์ใหม่อัตโนมัติ

ถ้าเครื่องใดเคยพิมพ์ที่อยู่เซิร์ฟเวอร์เองไว้ ให้เปิด **การเชื่อมต่อเซิร์ฟเวอร์** ที่หน้าเข้าสู่ระบบ แล้ววางที่อยู่ใหม่

## ขั้นที่ 8 · สร้างบัญชีพนักงาน

เข้าสู่ระบบด้วย owner → เพิ่มเติม → ทีมงาน → เพิ่มผู้จัดการและพนักงาน (บัญชีเดิมใน Google Sheets ไม่ได้ย้ายมา)

---

## กันฐานข้อมูลหลับ (แผน Free) — Vercel Cron ทุกวัน

โปรเจกต์ Supabase แบบ Free จะถูกหยุด (Paused) เมื่อไม่มีการใช้งาน 7 วัน แอปมีงานอัตโนมัติ `/api/keepalive` ที่ Vercel เรียกวันละครั้ง (ตี 3 เวลาไทย) ให้ฐานข้อมูลทำคำสั่งเล็กๆ 1 ครั้ง จึงไม่ถูกนับว่าว่าง
- ตั้งไว้ใน `app/vercel.json` (`crons`) และ `app/api/keepalive.js`
- ดูผล: Vercel → โปรเจกต์ → **Cron Jobs** (กด **Run** เพื่อทดลองได้) และ **Logs** (ค้นหา `keepalive`) — ต้องเห็น `"ok":true`
- เมื่ออัปเกรดเป็น Pro แล้วไม่จำเป็นต้องใช้ แต่เปิดไว้ก็ไม่เสียหาย

## เมื่อมีปัญหา

| อาการ | ทำอย่างไร |
|---|---|
| ลืมรหัสผ่าน owner | `node tools/supabase_setup.mjs --reset-owner` แล้ววาง URI ระบบจะให้รหัสผ่านชั่วคราวใหม่ |
| แอปขึ้น "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" | เปิดที่อยู่ในขั้นที่ 4 ด้วยเบราว์เซอร์ ถ้าไม่ขึ้นข้อความ ให้ดู Supabase → Edge Functions → api → Logs |
| โปรเจกต์ Free ถูกหยุด (Paused) | Supabase → Restore project หรืออัปเกรดเป็น Pro |
| ต้องการกลับไปใช้ Google Sheets ชั่วคราว | ใส่ที่อยู่ Apps Script (`…/exec`) ใน `app/config.js` แล้ว deploy แอป — ระบบเดิมยังอยู่ครบ |

## สำหรับผู้พัฒนา (หลังเปิดใช้งาน)

- แก้ `app/js/core.js` / `server/*.js` แล้ว: `python tools/build_backend.py` → `npx supabase functions deploy api --no-verify-jwt --use-api`
- เพิ่ม action ใหม่: `node tools/trace_tables.js` (สร้าง `server/manifest.json` ใหม่) แล้ว build + deploy — ถ้าลืม ระบบยังทำงานถูกต้อง แต่ช้าลงสำหรับ action นั้น (ดูคำเตือนใน Logs)
- เพิ่มคอลัมน์หรือตารางใน `SCHEMA`: `node tools/pg_schema.js` (สร้างไฟล์ migration ใหม่ ไม่แก้ไฟล์เดิม) → `npx supabase db push --remote`
- ทดสอบทั้งหมด (รวม Postgres จำลองด้วย PGlite): `npm test`
- สำรองข้อมูล: แผน Pro สำรองรายวันอัตโนมัติ (Database → Backups)
